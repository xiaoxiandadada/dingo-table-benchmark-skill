# 渲染、定位和飞书写回

从原 HTML 渲染，不能用生成式图像工具重绘表格文字来充当预测证据。统一字体/边框以便比较，保留文本、行列及合并关系。直接 HTML、HTML 文档及多 table 都要支持。非法或截断输出可以显示局部内容，但必须醒目标 incomplete，不能称完整结果。

曾出现 Astra 图只有标题：空 thead 与渲染兼容问题会使整表消失。应移除无行的 section wrapper（仅展示层）、检查布局中实际 td/th 计数、检查图片正文高度，并在上传前逐张/分段视检。仅确认 PNG 能打开或上传成功是不够的。

错误记录：sample_id、model、零基 td/th 文档序索引、原图行列位置、observed、expected、type、confidence、review_method。遗漏项不存在可框单元格时用邻近格定位，文字明确是缺失位置，不误称邻近格本身识别错。模糊原图、可接受表示差异及参考金标疑点单独记录。

用户指定某章内嵌表格时：先读取 docx/wikidoc，提取实际 sheet token；不要误更新另一份外链表格。再完整读取表结构与样本行映射，按实际行号定位。

建议列：问题定位、样本 ID、问题类别、PDF 页码、原图、Astra、六模型、状态。每行第一列每模型一句话，高置信错误在对应模型图上红框，未见明确问题如实注明。不要默认每张 Dingo 问题表的六模型都错误。

使用当前可用的飞书 skill/CLI：cells-set-image 绑定单元格；图片相对路径按工具要求；保留原图和用户编辑。每次上传保存目标单元格及图片 token，失败从该格重试。回读匹配全部 token 与样本，不只计数。同步检查实际图片正文，杜绝空白渲染上传。

发布到 GitHub 时把可复用工具与真实数据分开：默认不含密钥、内部 endpoint、S3 路径、签名下载 URL、飞书资源 token、业务 PDF/截图、模型权重。用户授权 GitHub 上传不等于数据权利清理完成。匿名聚合结果可独立保留，历史局限需一并说明。
